# Spike 2: implementation decisions and learnings

## 2026-10-09: automatic inventory tools

Explicit equip/unequip commands and citizen equipment references are removed. Work and combat automatically use the highest-tier matching tool available in inventory; sell escrow and reserved inputs are not available inventory. Every carried tool can be sold or gifted. Autonomous livelihood reserves remain preferences, not market restrictions.

Servicing remains per citizen/tool kind. Harvest duration stays captured at work start (after travel), with ongoing prerequisite checks; combat selects its sword at each strike. Selling a required tool can therefore invalidate harvesting, without recalculating already-started work duration.

Legacy checkpoints validate equipment references before discarding them without adding items. Obsolete queued/plan steps are removed; surviving plans with renumbered steps receive a distinct identity so historical receipts cannot collide with future receipts. Historical research and receipts retain their original terminology. Typechecking, production build and the ordinary test suite passed; no live model or browser run was needed.

### What exists

Spike 2 uses `.prosper-v2/`.

### Decisions made while building

- **Queues:** replace by default, append explicitly. Inputs reserve when an action starts, not while queued. Invalid replacements retain valid current work. Queued actions revalidate on activation; failed queued actions report their error and allow following entries to try.
- **Sight:** Manhattan radius 3, centrally configured; walls are transparent. Other citizens' private plans/inventory remain private. Physical entity targets need current sight; travel to dated coordinates first. Public markets/messages and addressed owner alerts remain explicit exceptions.
- **Construction:** visible site required when work starts, including queued activation. While an accepted build detours outside sight, it does not probe remote occupancy. Dynamic prerequisites are checked again when visible and before completion.
- **Physical time:** one authoritative tick loop, separate from reasoning and animation. Browser refresh, reload downtime and animation frame rate never advance the world.
- **Reproduction:** explicit consent to each other, expiring after 100 ticks; both parents occupied for 24 ticks. Each pays 3 T2 food, requires health 75 and receives a 1,000-tick cooldown on completion. Cancellation returns each parent's unconsumed reservation. New citizens start health 100/fullness 60 with no holdings or minted gold. See `src/world/config.ts` for current balance authority.
- **Continuity:** durable goals, bounded dated notes, execution/queue and last result; fresh model context each turn, without carrying a hidden reasoning transcript. Context includes parents and consent/cooldown state. More elaborate memory is not justified yet.
- **Reload:** an independent supervisor and stable API proxy coordinate checkpoint acknowledgement before child termination. Aborting requests alone is insufficient: generations/run/turn identity block late commands. The checkpoint retains runtime intent, fixture consumption and world state; a resumed clock starts a new interval with no catch-up.
- **Accounting:** independent append-only request/token ledger, reservation persisted before transport, uncertain requests still charged. This is not a verified dollar budget. Old reference USD prices were deliberately not reused.
- **Timeouts:** bounded live-request deadlines release stuck thinking slots while preserving uncertain charges and physical work. Default is 120 seconds; late usage receipts may reconcile accounting but cannot apply commands.
- **Rendering:** SVG was sufficient for the implemented scene. Shared-tile offsets, distinctive sprites, motion/work cues, a roster and normal HTML dossiers provide useful readability and automation. No game engine was needed.

### Concrete problems found and corrected

1. **A stale deposit is not a live target.** The initial scripted planner repeatedly attempted to harvest a remembered deposit outside sight. It now travels to the dated location before trying, and explores unexplored frontiers rather than bouncing along the map boundary.
2. **Validation can leak knowledge.** An unseen wall construction request initially exposed whether another citizen occupied/reserved the tile. Visibility gating and deferred out-of-sight revalidation now prevent that tool path from disclosing remote activity.
3. **Historical citizens are not permanent corpses.** Keeping dead citizens for history initially left a second visible entity after loot collection. Living projections and separate body/loot records now reflect disappearance correctly while retaining dossiers.
4. **Noncooperative requests need a local deadline.** An ignored abort or hung provider must not occupy every citizen reasoning slot forever. Deadline tests cover slot release and late-response rejection without stopping the world.
5. **SVG browser focus behavior matters.** Chromium's default large SVG focus outline obscured the scene. Explicit keyboard focus styling retains accessibility without covering the map.
6. **Cold startup differs from a warm test run.** Dependency recompilation exposed a 20-second browser readiness timeout. The harness now allows a bounded 60-second cold start and retains the last readiness/error response rather than hiding the diagnostic. Browser acceptance passed after this change.

### Evidence collected

- Core tests exercise tier progression, travel/work reservations, cancellation, owner-only processing, exact escrow settlement, destruction, death loot, consent and joint-action cancellation.
- Runtime tests exercise actual child IPC handoff, corrupt/incompatible restore refusal, partial work and paired-action restoration, no downtime catch-up, repeated saves and late provider responses.
- Headless browser tests exercise selection/dossiers, play/pause/step, knowledge mode, camera controls, keyboard/reduced motion, selection persistence and actual backend restart with run identity preserved.
- Image-capable browser inspection found recognizable humanoid characters, distinct resources and readable work progress/dossiers. Names are small at full-map scale; zoom and roster are the available alternatives. Mobile layout avoids horizontal overflow.
- A scripted `progression`, seed 1, 360-tick trial kept all 3 citizens alive, completed 20 harvests and 2 crafts, and preserved all 300 gold. Three depleted-deposit command errors were reported rather than hidden.
- A scripted `village`, seed 1, 1,200-tick trial kept all 6 citizens alive, completed 255 harvests and 36 crafts (including higher-tier equipment), and preserved all 600 gold. Forty depleted-deposit errors show contention remains useful diagnostic evidence; no provider requests were made.

These scripted trials demonstrate mechanics and iteration tools, not spontaneous cooperation, trade, reproduction or conflict. The scripted planner currently does not construct stations or exercise every implemented rule.

### Remaining empirical questions

- Ollama's local catalog is reachable and includes `deepseek-v4.1-flash:cloud`. No inference was performed during implementation. Actual cloud access, high-reasoning/tool compatibility, usage reporting and live citizen behavior remain unverified.
- Request/token limits are conservative accounting controls, not verified billing prices or a dollar spending cap.
- Recorded fixtures can reproduce tool-response sequences with no paid calls. They are not an automatic exact historical replay across asynchronous timing or changed mechanics. Diagnostic command ordering/ticks provide evidence for constructing retained cases.
- Memory effectiveness, observation size, spatial competence and review cadence need short live trials. Start with observed failures and completed work, not more systems or prompt complexity.
- Checkpoints persist on coordinated reload or explicit save. Abrupt crashes do not recover every unsaved tick; no crash-proof event-sourced guarantee is claimed.

## Layered overnight redesign (2026-10-08)

The current design supersedes the preceding turn-by-turn harness and its 40,000-token allowance. New worlds run a continuous local controller; optional model calls revise policy in one response. Survival, routing, production, commerce, negotiation and immediate conflict no longer depend on inference. Actual traits and personally witnessed disputes create different local motives; aggregate emergence does not require a model, and local-rule evidence is distinct from model intelligence.

The largest savings came from removing dialogue and unnecessary admission. A normal 100-founder, 6,000-tick mock-policy trial selected 23 reviews over 45.61 simulation citizen-hours; stable early periods selected none. Global wall-time spacing, a rolling hourly ceiling and finite durable budgets prevent accelerated ticks/reloads from accelerating spending. The final late-society whole prompt is about 18KB, compared with 126–139KB for the historical surface in the same cross-section. These are serialized bytes, not billed tokens.

Provider ergonomics mattered: local constrained generation needed explicit context size and a tuple-schema representation Ollama accepted. A valid response can still be strategically useless. One late-swarm continuation produced exactly the existing outcome; an aggrieved citizen's revised toll earned eight additional gold in a small paired 600-tick branch. Four sequential cloud probes consumed 19,268 reported tokens. No dollar cost or broad model ranking follows from that sample.

Strict mechanics had to expose usable strategic levers: contact-seeking and durable family rendezvous, revocable consent that survives ordinary travel, explicit null withdrawal, hard no-go routing and faction renunciation. Public claims are demands enforced by bodies, not magical ownership. Significant-event retention and notebook-free spectator snapshots make the results watchable without exposing private facts to citizens.

Economy experiments found limited recurring fibre demand and serious oversupply. Material servicing creates modest demand; stock/escrow/sales/public-demand saturation reduces pointless extraction. Founder survival and conserved gold do not mean the economy is complete: some children still starve without liquidity/known food, and many citizens hold no gold. See [final evidence and limitations](OVERNIGHT.md), [seeded world research](overnight-world-research.md) and [independent review](overnight-review.md) for retained trajectories, exact receipts and verification.

## Clean-slate world-first presentation (2026-10-08)

The user superseded the always-visible workbench layout. The world now owns the default workspace, with a bounded activity strip and panels opened only on demand. Citizen selection opens a dossier; messages, settings, accounting and diagnostics do not compete for permanent map space. The Scene stays mounted while drawers change, preserving manual navigation and the confirmed motion/follow pipeline. Compact map guidance replaces always-visible explanatory legends; optional speech bubbles default off.

Analytics are organized by questions rather than a wall of receipts: population/wellbeing, market prices and actual settlement windows, and resource stock versus open demand/supply. All histories use existing retained telemetry. No history is reconstructed, missing quotes/skipped windows remain gaps, and wellbeing uses a fixed 0–100 scale. Commodity checkbox colors are keyed to the item, not selection order. Chart maxima are computed once per render so many selected series do not repeatedly rescan the complete dataset. Exact sample and recording explanations remain available without occupying the initial plot area.

Visual checks exposed inherited light-card contrast failures inside the new dark shell and a summary/chart shared-grid row that pushed cards below the drawer. Explicit component colors and an independent summary column fixed them. A first-pointer-click regression reproduced the range focus handler resetting the selection before native pointer handling; pointer-origin focus now waits for the native value, while keyboard focus still announces a sample. Previews used a paused Local AI runtime copied from the saved checkpoint into OS temp; source edits did not touch the durable run or invoke a provider. Browser fixtures cover the new workspace, confirmation/privacy boundaries and preserved camera/motion behavior. Root grid rows are explicitly assigned so an empty, hidden notice area cannot consume the activity strip's row. Desktop plots reserve a stable exact-value column, preventing focus/hover from moving the slider or hiding its first click; optional audit details scroll separately from the initial graph. The active browser configuration now targets the replacement workspace and migrated real-backend/accessibility/motion checks; obsolete always-visible-workbench fixture files are retained rather than deleted. Full unit verification also exposed a random-seed-dependent reset test assumption: founder IDs can change with procedural deposit allocation, so late-response protection is asserted across the fresh citizens instead of indexing by an old founder ID.
