# What is this project

The goal of this project is to experiment and determine the feasability of a game, that places the user in the role of a key figure in governance, where they decided the policies of the population. Perhaps this will change as we develop, where things end up more like traditional city builders, where the user places roads buildings etc and the world reacts to it.

The goal is to expirement with top of the line intelligence citizen ai, by combining a variety of techniques (yet to be set in stone) such as 'jev' like models, small llm's and more traditional programatic means, ie path finding task management. Combining these different mediums in a layered aproach, such that the entities have some form of long term planning / goals, personality, medium term goals, and short term goals / tasks, as well as memories and a medium to comunicate with other entities. I envision that all entities communicate via  a 'phone' which provides global communications at a cost (as to prevent spam and thus bloat / context rot, we only want important coms).

What I aim to see, without biasing things, is emergant constructs, ie more ambitious entities will search for busines oportunites and exploit them, hire staff, influence governance, trade with other cities / towns etc.

The high level goal can start with a few citizens, and have things grow into a town and compete with neighboring towns. Basic combat should exist, such that things may get hostile in tense situations, ie say a population is starving, and the other town refuses to trade their food, then as a last resort the citizens can conspire to wage war against the other town. So essentially the goal is to prosper, progress, form bussiness, specializations, wage war and overall propser.

About the world:
I think we can keep this very simple. Simple but with nuanced interactions, such that complexity may emerge, like things do in real life.
Agents should have a small set of possible actions, however from this emerges complexity. They do not need to be human like, but they need to be 'smart'.

## Citizen sandbox spike

Eight starting adults inhabit a 20 by 16 world. DeepSeek V4.1 Flash makes strategic decisions through a bounded tool loop; deterministic code handles routes, harvesting, construction, needs and care. Citizens can communicate, escrow offers, exchange goods, build bakeries, walls and houses, form families and fight. There is no currency, employment, governance or contract enforcement yet. Personalities and aspirations are deliberate biases; the spike does not establish unbiased or guaranteed emergence.

### Run

Use the checked-in Node 24 and npm versions:

```powershell
npm.cmd ci
npm.cmd start
```

Open http://127.0.0.1:4173. The server starts paused. Play starts simulation and strategic turns; Pause stops ticking and new turns, while in-flight reasoning can finish. Reset replaces the world but preserves spending. Closing the browser does not stop the server. `npm.cmd run dev` watches backend code; restarting creates a new world unless you explicitly restore a checkpoint.

The model is [`deepseek-v4.1-flash:cloud`](https://ollama.com/library/deepseek-v4.1-flash) through the signed-in local Ollama service at `http://127.0.0.1:11434/v1`. The previously selected dated V4 Flash tag was retired on September 25, 2026; V4.1 currently exposes a cloud alias rather than a dated tag. Prosper never copies Pie credentials. Optional settings: `PORT`, `OLLAMA_BASE_URL`, `PROSPER_MODEL`, and `PROSPER_REASONING_EFFORT=low|high|max`. Reasoning defaults to **low**, with an 8,192-token output ceiling per provider call. The planner inspector reports actual turns, model calls, tools and errors separately.

The startup connection check verifies Ollama's local model catalog, not cloud availability. A cached retired tag can still appear there. HTTP 410 now blocks planning for all citizens, reports the configured unavailable model and requires selecting a supported model/restarting; automatic retries stop, while existing physical execution continues if the town is running. Retry cannot make the same known retired tag ready through its cached listing. Provider response bodies remain private. Real remote access is verified by an actual model call, not the catalog check.

Returned reasoning is retained privately between tool calls within one turn, then discarded. It is excluded from audit requests, citizen state and subsequent turns. Its size counts toward the turn's context and spending bounds. The planner state reports `reasoningHistory: within-turn`; audit responses retain only reasoning metadata.

### World and starting citizens

New worlds are 20 by 16 (320 tiles), with eight adults, **12 food sites and 10 trees**. The original four citizens begin in ring 1; Neri, Bram, Tavi and Edda begin in ring 2, one per quadrant. Every starter can initially see a food site. Resource sites are deliberately sparse: 22 total instead of the previous 40. Higher quality means **more goods per harvest only**; effort, stock capacity and regrowth do not change with quality.

There are **three tiers total: center, ring 1 and ring 2**. The separate region **`center`** has the best sites, with two surrounding rings getting worse outward. Outside center, areas combine a compass quadrant and ring, for example `north-west-ring-1` and `north-west-ring-2`; all four quadrants have both rings. Ring numbers increase outward; resource levels increase with quality. Center is x 6–13/y 5–10 (48 tiles); ring 1 is the surrounding part of x 3–16/y 3–12 (92 tiles); ring 2 reaches the map edge (180 tiles). Each ring excludes the regions inside it. North/south divide at y 8 and west/east at x 10. A bare quadrant covers its two rings and excludes center.

| Region | Resource level | Food per harvest | Wood per harvest |
| --- | ---: | ---: | ---: |
| Center | 3 | 3 | 15 |
| Ring 1 | 2 | 2 | 10 |
| Ring 2 | 1 | 1 | 5 |

At **every level**, crops take 6 base harvest ticks and regrow 99 ticks after harvest; trees take 8 base harvest ticks and regrow 120 ticks. Tools reduce effort as before. Stock 0/1 counts harvest opportunities, not individual goods: one successful harvest consumes one opportunity and pays the whole bundle, potentially exceeding a collection target. Competitors do not both receive the same harvest.

The layout has an ideal no-travel raw-food flow of 10.286/minute, supporting 24 adult equivalents before movement, competition and recovery; the previous uniform map supported 32. That is 25% less potential food and three times the nominal demand of the eight starters. Ideal wood flow stays 37.5/minute, concentrated into ten sites. Center has two crop sites/two trees; ring 1 has two/two; ring 2 has eight/six. Inner sites offer advantages worth bargaining over or protecting, while outer food remains available. Bread now restores 87.5 hunger, 25% more than 70 and 2.5 times raw food's 35. Automatic bread meals start at 87.5 hunger to use that relief fully; raw-food meals still start at 60. This creates a production incentive without requiring any particular strategy or conflict outcome.

Use exact area IDs to restrict movement, exploration, queries or gathering; routes may cross other areas. `move(area:"center")` enters center without revealing its entire contents. Quality geography is public; actual sites and their stock must be discovered through sight or dated reports. An area having a high resource level promises neither free stock nor access.

The map clearly shades and outlines center, with separate labels for it and the two rings; deposits show their level and actual yield in tooltips and citizen memory. The former vertical middle ridge is replaced by 20 scattered wall remnants and four rock tiles outside center. The ruins form short lines and corners with openings/detours; every walkable tile remains connected and the center stays open. Ruin walls are unclaimed, start at 60/120 health, block movement/sight and can be attacked to clear a passage for the standard nine-wood salvage. They have no citizen owner to notify, cannot be repaired as personal property and do not count as citizen-built structures. Rock tiles remain impassable terrain. Demolishing a ruin is not evidence of citizen hostility.

Citizen context, `get_places` and movement use the same region names. Classic four-quadrant and saved older two-ring checkpoints keep their original geometry, sites, structures and yields; reset or a fresh server creates the new layout. Current bread nutrition applies when old worlds are resumed.

Neri is cooperative and relationship-oriented. Bram is opportunistic and domineering, willing to use threats or violence for gain while avoiding losing fights. Tavi is neutral and transactional, reluctant to join feuds without a personal stake. Edda is territorial and distrustful, inclined to retaliate but open to useful truces. These complement the original citizens' personalities. They change personal aspirations and decision context, not combat rules, starting grudges, forced attacks or outcome quotas. Hostility still needs live observation.

### Citizen harness

Resource queries and automatic gathering rank personally known sites by estimated effort per yielded unit: `(max(route, recheck delay) + harvest effort + recent competition) / yield`. This lets a richer, slightly farther site compete with a nearby poor one. `find_resources(rank:distance)` requests nearest-first ordering instead. The score is an uncertain search preference, not a promise of harvest time or available food. Unknown sites are omitted; reported quality/yield stay dated. Eligible exchange results include an optional exact trade directive; equipment and production mechanics queries include optional upgrade/build directives with costs. These are choices for the citizen, never automatically selected actions. Crafting, construction, baking and rest schemas state fixed work durations separately from travel and gathering.

Mail that arrives during reasoning is checked against the proposed tasks, retained work, communications, trade counterparties and referenced sites/offers. Unrelated mail can remain unread while valid selected work commits; it retains immediate follow-up eligibility. Relevant correspondence, missing messages or inbox overflow still require fresh review. This applies to asynchronous semantic turns, including the final application check. It neither acknowledges unseen correspondence nor chooses a reply.

Rejected decisions report independent task format and placement problems together, with each action's required/optional fields. Validation remains strict and atomic; the harness never repairs or executes malformed choices. Observations distinguish persistent world capabilities from temporary end-of-turn tool restrictions, so memories claiming an ability is unavailable cannot override current rules. System & planner and retained request evidence show serialized bytes for tools, observation, instructions, public history and private replay; these are wire measurements, not provider template/tokenizer attribution.

The default is `semantic-tools`. Citizens receive a compact personal observation, immediate correspondence, execution progress and recent outcomes. The current place includes known supply rates, consumption and last-seen contacts; queries compare other areas or supply missing facts about resources, people, buildings, eligible escrow, history and mechanics. Supply estimates are upper bounds before travel and competition. No peer inventories or remote live stock are exposed. Named areas identify parts of the map, not biomes; summaries count personally known sites and show observation age. Navigation uses simulation geometry and route estimates rather than model-generated coordinates.

Phone and offer tools execute logical transactions during reasoning and return real IDs and remaining inventory. Private contact uses free speech when visibly nearby, otherwise a phone send costs one existing wood. Public posts cost one wood. Sends accept up to500characters; a post creates no goods, offer or consent. An offer escrows currently held goods, can be recipient-restricted, expires after 1,800 ticks and returns an ID that subsequent messages can reference. Each maker has one open offer across all recipients. Opening another requires replaceOfferId naming the current offer; accidental replacement is rejected without spending. Successful replacement receipts identify the cancelled offer, refund, new terms and sole active offer. Taking an offer, giving goods and reproduction require physical meetings using global citizen routing.

Both strategy tools accept up to two `communications` alongside physical execution. Each queued send takes two ticks and rechecks visibility/payment then; it has no sent-message ID until execution. Omit the field to retain pending sends; `[]` cancels them. A private reply names `target` (or the lossless `to` alias) and text; its type defaults to message when a recipient is explicit. A public post must explicitly use type post. Pending own communication appears in observations, and the UI labels nearby speech within Private messages.

The current observation previews four eligible exchanges, prioritizing actual offers referenced in the inbox and then recent offers. Terms state what you pay and receive; omission counts indicate further offers. This selects evidence, not an action or reservation. `get_exchanges(after:nextAfter)` retrieves further bounded pages and own offer history. Stale trade rejections attach current eligible alternatives rather than requiring another query to recover.

Personally seen contacts also retain a small physical activity snapshot, such as harvesting, moving, baking or attacking. The same observation age applies to the activity and location. Resource queries include last-seen harvesters at that site; these are dated sightings, not a live count of competitors. Moving exposes no destination, and an action target is included only when it was also visible. Sightings also retain equipped tool/shoe/weapon levels, with the same age; remote upgrades or breakage do not refresh them. Exact durability, private plans, goals, inventory and message contents are not observable. Voluntary location reports share position only.

`move(target: citizenId)` routes globally to that citizen and follows their movement, even outside sight. Giving, trading, reproduction and attacks automatically use the same routing; citizens can choose an interaction directly without exchanging locations or queuing a separate movement step. A citizen target takes precedence over an optional area hint in older plans. Travel takes time, obstacles can make targets unreachable, and finite actions retain their timeout. Effects still require adjacency and normal resource, consent and eligibility checks. This intentionally relaxes fog of war for navigation, including hostile pursuit; remote observations and private state remain restricted. `move(area)` and movement to known static sites retain their existing behavior.

Chosen social actions prepare their own requirements: giving/trading gather missing raw food or wood, and reproduction gathers its own inputs and rests for its own health requirement. Missing bread requires a separate production/exchange choice. Temporary joint reproduction failures after actual contact retain the action for a later attempt; consent withdrawal, an unavailable offer, an unreachable target or the 600-tick action timeout still stops it. No partner's strategy is changed, and no consent or gift is invented. Execution observations show preparation progress.

`continue_strategy` retains current execution and invested work. `commit_strategy` replaces it with up to four serial directives followed by optional repeating work. `ensure_inventory(resource,minimum,area?)` gathers until TOTAL stock is at least minimum, including consumption during travel; repeating `gather` work continues collection.

Stock targets persist until reached or revised, with current/best stock, gap, elapsed time and time since a new peak reported; other finite directives retain the 600-tick timeout. Areas can restrict discretionary search.

`collect(resource,amount,maxTicks?,area?,target?,camp?)` instead attempts NEW units within a time budget (default 60, range 1-600 ticks), then continues the queue with what it obtained, including zero. Meals do not undo collected units. Optional target prefers a known matching site; camp:true explicitly stays at that target, including when empty. Area and target must agree.

Automatic routing reconsiders a destination when personal sight shows other harvesters occupying all stock, and avoids starting another automatic harvest there. This is no reservation: explicit camp can still contest it, and remote reports do not block a site. Automatic routing can depart before nominal regrowth when its travel time reaches the dated estimate. Only a witnessed stock drop establishes that estimate; empty sightings alone do not reveal harvest time, and an overdue estimate never guarantees available stock. A primitive already underway or urgent care may finish before the deadline is checked. Use this for optional preparation; hard inventory prerequisites remain available. Results report actual collection and whether the amount or budget ended the task. Existing internal `acquire` orders are presented through this same semantic interface; no capture migration is needed.

The simulation selects nodes, rechecks depletion, explores and handles routes. Bakery construction, equipment, baking and repairs gather missing inputs.

Reproduction requires two consenting adults in adjacent contact, each with at least50health and 2food equivalents (2raw food or1bread, raw food first). It costs no wood or energy and has no hunger gate, reproduction cooldown or population cap. The action takes4ticks; successful birth consumes consent, so another birth needs a new agreement. Children mature after300ticks. Goals and messages alone do not execute physical actions.

Physical work continues during reasoning and mail review. Concurrency is configurable (1-8 turns); starts are spaced one second apart by default. Provider selection and the measured default are described below. Materially worsening distress has first priority. Within a priority class, the citizen who has waited longest while eligible goes first. After two priority turns ordinary work precedes mail; after 30 real seconds of continuous eligibility, an aged request outranks fresh mail. Waiting time accrues even while both model slots are occupied, and class changes retain it. This is promotion priority, not a 30-second service guarantee: active calls, distress and earlier queued requests can still delay a turn. Pausing clears queue age; backoff and normal eligibility gates remain. The inspector shows actual queued seconds, and dispatch audit records queueWaitMs.

Ordinary reviews require the chosen 180-600 tick horizon (native default 600) and a wall-clock floor of max(5, 60 / selected speed) seconds, so 8x no longer adds an unrelated 60-second delay. Expected milestones advance an already chosen queue or repeating policy without asking the model to approve each step. Exhausted work, failures, relevant social events, distress and the chosen review horizon still prompt decisions. An inventory target with no new stock peak for 120 ticks prompts a progress review, at most once per 120 ticks; it does not cancel the target. Completion/failure reviews require 24 ticks and max(5, 15 / selected speed) seconds. Native distress reviews bypass tick spacing and use a cooldown of 15 seconds divided by selected speed; global spacing and provider-error backoff remain. Empty food/bread with hunger at least75, or health below50, can request a review when that risk materially worsens. Private mail bypasses per-citizen cooldowns.

A tool turn is bounded to six calls per response, eight model steps, twenty tool calls and two minutes. A batch above six is rejected entirely without actions; every call receives an error receipt so the model can recover within the remaining turn budget. Exceeding twenty total still stops the turn. A whole-turn deadline is reported as a decision failure, separately from transport/HTTP failures, retaining paid partial usage and current work. Before every model step, one current observation replaces the previous one without adding routine-progress alert messages. At the request boundary it follows the complete tool receipt batch, so earlier rejected plans precede current facts. Refreshes and stale-decision errors replace it; repeated identical read queries supersede their earlier results. Action receipts, errors and tool-call pairing remain. Plain-text scratch reasoning is limited to 16,000 bytes; older whole entries are omitted first. Codex encrypted replay stays private within the turn.

Schemas share repeated definitions without weakening runtime validation. The Ollama adapter expands references at typed property boundaries and describes bounds its parser drops; raw array-item schemas retain their definitions. Equivalent JSON-encoded objects/arrays are decoded only where structured fields are expected. Message text, quantities, targets and unknown fields retain their original validation.

The 48,000-byte facts/tools and 128,000-byte total limits remain defensive guards; context pressure after the first tool batch, an initial context exceeding the hard facts limit, the final three steps,75elapsed seconds or insufficient time estimated from the latest call restrict tools to continue/commit, reserving recovery time within the two-minute deadline. Context refresh is automatic; decision-only steps remove obsolete plain-text scratch reasoning. Rejected decisions identify the invalid task and preserve prior successful action receipts.

Transient provider failures back off the affected citizen for at least 60 seconds, honoring Retry-After up to five minutes; exhausted budget pauses spending. Active failures appear in the top banner with citizen, HTTP status and retry timing. Another citizen succeeding cannot hide them. System & planner retains 20 recent failures (shows the latest six), marks recovery and reports mean turn/call latency, request bytes, input tokens per call and concurrent turns. History is per server session; durable audit retains provider-error records. Needs, retreat and dependent care continue independently.

Hungry food collection with no progress becomes review-eligible after 120 ticks when no food or bread is held, including an explicit camp; harvesting resets that clock. Review retains the chosen work. Personal foodUrgency reports an approximate starvation/fatal-hunger horizon assuming no food, healing or other harm; actual meals replace that estimate.

Selected speed remains authoritative, including during starvation. Hunger stays on a 0–100 scale and rises 0.25/tick for adults and 0.15/tick for children; starvation at 100 drains 0.5 health/tick. A full adult takes 400 ticks to reach starvation and another 200 ticks to die from hunger alone. Raw food restores 35 hunger; bread restores 87.5, clamped at zero. With bread held, automatic eating starts at 87.5 so a loaf covers 350 adult ticks; otherwise food meals/emergency foraging start at 60. Chosen food gathering retains its area/target and harvest progress during hunger; meals and rest still interrupt it. Other tasks retain automatic emergency foraging.

At starvation, a chosen food camp or restricted area whose next estimated meal cannot arrive before fatal hunger can yield temporarily to personally observed food reachable in time. This retains the strategic order/queue and resumes it after eating; already invested feasible harvests continue. Stale reports, remote live stock, contested units and meals too far away cannot justify this fallback. Estimates and future regrowth remain uncertain. Hungry food buyers can similarly prepare wood across multiple fresh known trees; travel, harvest effort, competing harvests, remaining survival and offer expiry are rechecked before proceeding. The engine does not select an offer or promise a successful meal.

The live semantic toolset has no deliberate `wait` directive. Citizens are guided to keep useful work going between milestones and while awaiting replies, with follow-on work suited to the completed queue. Rest remains available for recovery. Gathering can still pause internally to recheck depleted resources; removing explicit waiting does not remove regrowth or force arbitrary movement. Old checkpoints and the retained legacy comparison harness still support historical wait tasks.

Behavioral guidance treats life, health, dependents, livelihood and independence as real stakes. Citizens should work to escape deprivation, protect themselves and improve their standard of living with useful equipment, supply and influence as fits their character. Preparation should be proportional to the next action; compare waiting with buying, changing methods or a smaller useful outcome. Communication should seek practical offers, help, cooperation and clear boundaries, then turn agreements into actions. Guidance encourages initiative toward each citizen's aspirations: notice possible advantages, investigate relevant uncertainty, take useful affordable actions and revise methods from results. Cooperation, independence, bargaining, withholding, defense or aggression remain personal choices. Citizens speak in character with natural, concrete requests and offers rather than tool names or internal planning jargon. Mechanical rules belong to schemas and queried references. An optional assessment {startedAt,status:completed|abandoned,reason} concludes the current undertaking before an optional successor in the same decision. The timestamp must match the current undertaking; the engine records the citizen?s assessment and reason without deciding success. Without a successor, physical work stays as chosen. A successor may reuse the same objective/condition for another instance. The latest closed own escrow is included as actual status evidence; further history remains queryable. Optional notes are bounded metadata; a long assessment reason is shortened with an ellipsis and explicit omission receipt. Its identity/status and executable choices remain strictly validated. Task errors show the selected action's required and optional fields. No communication frequency, prices, bakery quota or family outcome is prescribed.

Material mail, consent, failure, witnessed violence, worsening survival and citizen deaths update active tool turns. Survival updates report newly empty reserves at high hunger, hunger crossing75/90/100 while empty, or a further10health lost in distress. Dead targets return an explicit error rather than encouraging guesses at IDs. Racing mail, failures, violence and consequential completions reject a stale decision with fresh context. Independent replacement work can proceed through an unrelated consent or death update after live target validation. A chosen immediate guard/attack can proceed through further strikes in the same already witnessed attack; new attackers or targets still require fresh review, and no defense is chosen automatically. A chosen immediate food directive can proceed through worsening hunger/health; otherwise a starving citizen can spend every recovery step rejecting the very food work they need. These exceptions leave changed evidence unreviewed and request follow-up rather than claiming it was considered. Oversized immediate messages return a shortened draft and omission notice; only an explicit retry sends and charges wood.

Completed finite consequential actions (delivery, trade, reproduction, crafting, construction, baking, repair and attack) also update an in-flight decision. Observations retain up to six such completions plus an omitted count. A stale commitment receives fresh evidence and must be reconsidered; a final application check covers completion or survival deterioration after commitment. Existing execution is retained when a stale decision is rejected. Repeating an action deliberately after review remains valid. Routine harvesting, repeating production and synchronous phone/offer receipts do not create these completion interrupts.

The primary implementation is [agent-planner.mjs](lib/agent-planner.mjs), [citizen-tools.mjs](lib/citizen-tools.mjs) and [places.mjs](lib/places.mjs). [HARNESS-REBUILD.md](docs/HARNESS-REBUILD.md) records the design, evidence and ongoing iterations. [FINDINGS.md](docs/FINDINGS.md) records accumulated learnings. The [V3 contract](docs/V3-CONTRACT.md) describes world mechanics and the retained legacy harness; the semantic contract supersedes conflicting planner details.

Public history is searchable with `get_history(publicQuery,after?,limit?)`; results are dated public claims, paginated at eight posts, with no access to others' private mail. Omitting publicQuery retains personal history. New births receive broad, reproducible temperament and aspiration variety, retained on maturity; existing citizens keep their identities. The inspector displays personality. No professions or conflict outcomes are assigned.

Reviews include net food/wood/bread and health change since the previous accepted decision, recent personal memories, current own escrow, and the preceding undertaking when its objective changes. Three prior undertakings are retained for history queries; their status remains the citizen's assessment. Completed-action evidence focuses on events since the last decision. Family summaries use dated visual impressions of hunger/injury; remote exact vitals and inventories remain private. Adult relatives choose independently. Household parents retain living/deceased/unknown status after the already announced family death; older sightings cannot make a deceased parent appear available. The living directory supports bounded pages through get_people(after:nextAfter), so later citizens remain discoverable; optional area searches use remembered locations only.

Automatic resource selection discounts a freshly observed single-stock harvest race and recent personal losses, while respecting the chosen area or explicit legacy camping. The estimate expires and never reads remote live stock. A deliberately chosen food trade may gather a small missing wood payment from a recently seen stocked tree when preparation plus the meeting fits before fatal hunger; depleted, unaffordable or too-slow preparation falls back to emergency foraging. No trade is chosen automatically.

The bottom panel has three independently scrolling columns: Trades, Private messages and Public messages. Trades retain open and closed escrow with terms and status; private messages include family updates. Each column is newest first. Headers, roster rows and inspector spacing are compact; long messages show a three-line preview with Read more, retaining expansion through polling. Unchanged message rows retain their DOM so reading and keyboard focus are stable. Drag its dividers or use arrow keys to resize; widths are saved independently of the map layout.

### Equipment and demand

`craft(item,level)` upgrades tools, shoes or weapons from level 1 through 3. Omitting level means 1; each upgrade requires the previous level and pays its full listed wood cost. Missing wood is gathered automatically, followed by four crafting ticks. Existing checkpoint equipment counts as level 1.

| Equipment | Level 1 | Level 2 | Level 3 |
| --- | --- | --- | --- |
| Tool | 15 wood; harvest 1 tick faster | 60 wood; 2 ticks faster | 180 wood; 3 ticks faster |
| Shoes | 10 wood; 1.1x travel | 40 wood; 1.4x travel | 120 wood; 1.8x travel |
| Weapon | 20 wood; 18 hit / 12 counter; 12 uses | 80 wood; 27 / 18; 24 uses | 240 wood; 40 / 27; 40 uses |

Tools and shoes are permanent. Weapons wear on strikes and counters; a broken weapon is rebuilt starting at level 1. Unarmed damage remains 6 hit / 4 counter. These are meaningful uses for surplus and potential demand for inputs, not mandatory purchases. Equipment itself is not transferable; citizens barter food, wood and bread. Mechanics, context and the inspector expose levels and effects.

### Property, construction and conflict

| Building | Wood | Work ticks | Health | Wood recovered on destruction |
| --- | --- | --- | --- | --- |
| Bakery | 50 | 30 | 240 | 30 |
| Wall segment | 15 | 10 | 120 | 9 |
| House | 60 | 30 | 180 | 36 |

These durations exclude travel, gathering and interruptions. Selected construction gathers missing wood automatically. Walls block everyone, including their owner, and are built from an adjacent tile. A living citizen cannot be covered by a wall. All living buildings block line of sight; terrain and objects behind them retain their last-seen information until seen again. Bakeries remain walkable. A house admits its owner only and fits one person.

Rest inside an owned living house has **+300% recovery, or 4x the normal rate**: a five-tick rest grants up to 140 energy instead of 35, capped at 100 total energy; fed sleeping health recovery is 2 per tick instead of 0.5. Bonuses do not stack. `rest(target:'own')` routes to an owned house, including one just built earlier in the queue; a known owned house ID selects a particular home. Rest without a target stays at the current location. Automatic needs do not send citizens home, and destroying a house immediately removes its bonus.

Citizens describe geometry through `plan_construction`, using a personally known resource or building as an anchor. It previews a line of up to six walls, or a small/medium/large enclosure with at least one open entrance. The tool returns the cost, effort, route warnings and an exact `construct` directive; it builds nothing and reserves no resources. Code handles tile placement and routes. Plans require an explored, free footprint and usable entrance; construction reports retained progress and prepares materials one segment at a time. An explicit area restricts placement; otherwise a plan may cross geographic boundaries. Open entrances remain ordinary terrain accessible to everyone. A direct wall build also accepts a side and length relative to a known anchor. Citizens should leave escape and supply routes instead of trapping themselves or others.

An attack on any building immediately tells its living owner who attacked, which property was hit and its current damage. The alert refreshes that property's remembered destination, so `move(target:buildingId)` can approach it outside current sight. It does not reveal the attacker's remote position or inventory. Property danger receives distress review priority, but model response time still depends on active calls, queueing and cooldown. Citizens decide whether to retaliate, negotiate, flee or repair; defense is not automatic.

Owners may attack their own buildings to demolish them. The final strike on any building gives the destroyer 60% of its original construction materials, rounded down, once; repairs add no salvage. Killing another citizen transfers their food, wood and bread, including their outstanding escrow, to the killer. These stakes appear in every strategic observation. Buildings and equipment are not inherited by the killer.

Guidance treats citizens as independent game characters: strangers start neutral, and cooperation, bargaining, exclusion, threats and violence are available according to personality, loyalties and consequences. It encourages action and self-interest without required fights or trade quotas. A compact property summary and paginated `get_buildings` queries expose existing owned capacity before another purchase. Extra bakeries create no extra worker or production multiplier; current buildings are preserved, and citizens may decide to retain or demolish them.

### Persistence and diagnostics

The world is in memory. `node scripts/checkpoint-run.mjs --pause` pauses ticking/new turns, drains active reasoning and writes a unique fresh checkpoint. Without --pause it only captures an already paused town. If draining times out, leave the paused server alive and retry; no checkpoint is written and no process is stopped. Capture a paused state with no turn in flight before restoring it. Restoring a chosen checkpoint preserves world, knowledge and pending execution; the server starts paused. There is no browser import endpoint.

The authorized **$20 total** cap and `.prosper/usage.json` survive resets and restarts. Prior $3 and $10 ledgers migrate without removing charges, reservations or history. Reference rates remain $0.15/million input tokens and $0.50/million output tokens, including the earlier conservative $0.10 reserve; this is local accounting, not a provider invoice. Each provider step reserves an upper bound before sending and settles actual usage. Failed or usage-less requests remain charged. Never delete or reset this ledger.

The bounded `.prosper/audit.jsonl` trace records projected requests, tool arguments/results, reasoning metadata, accepted/rejected strategies and execution outcomes. It excludes credentials and reasoning text. Rotation retains the current file and two 2 MiB archives; experiment captures preserve selected evidence. Citizen messages and spectator data are diagnostic information, not extra citizen knowledge.

Ledger writers briefly retry genuine lock contention; persistent or unknown locks are preserved. A busy ledger is a visible retryable planning issue, while actual exhausted or invalid accounting still stops spending. A citizen dying during reasoning discards that turn without a misleading provider failure; any paid partial usage remains counted.

The desktop UI has resizable citizens, world and inspector panels above a combined feed. Overview is spectator truth; Citizen view shows only personally explored/remembered information. UI source is in `ui/`; `public/app.js` is generated by `npm.cmd run build:ui`. Static changes can be rebuilt and reloaded without replacing a running world. Numbered citizens use their ordinal on map tokens; family links collapse with living/deceased counts, and stock orders show their target and current holdings. A monotonic display clock follows recorded orthogonal movement without resetting on repeated polls; shared-tile offsets ease into place. The read-only browser capture tool in scripts/capture-ui.mjs uses an existing Playwright installation (explicit --playwright-module path), blocks simulation controls, and captures frozen screenshots or live motion samples with --live.

### Provider capacity and compact requests

The default is Ollama DeepSeek V4.1 Flash with low reasoning, six concurrent citizen turns and one-second start spacing. Six slots were selected in earlier GLM experiments, not a DeepSeek capacity comparison. In that historical eight-citizen Ollama comparison, four/six/eight slots took 85.9/55.3/57.2 seconds with all 24 decisions committed and no provider errors. Queueing subsequently remained material. The earlier four-decision social probe used GLM, as its request audit confirms; it was initially misattributed to DeepSeek and establishes no DeepSeek behavior or capacity result. No provider rate limit has been demonstrated; continue measuring live call patterns and congestion. Detailed measurements and limits are in [the overnight record](docs/OVERNIGHT-2026-10-07.md).
